# BROwOS Roadmap

Текущий этап — **0.1.0 preview**. Roadmap описывает реальные направления работ,
а не гарантированные даты и не автоматически завершённые GitHub Issues.
Текущие доказательства вынесены в [DEVELOPMENT_STATUS.md](docs/DEVELOPMENT_STATUS.md).

Окончательный GitHub CI и публикация подтверждаются отдельными реальными прогонами.

## Следующий приоритет: надёжная приёмка

1. Выполнить итоговый общий quality gate после объединения модулей; использовать
   уже пройденные E2E как приёмочные сценарии и расширять их для конкретных ошибок.
2. Объединить проверенный feature PR в `main`, дождаться успешного CI и проверить
   реальную загрузку GitHub Pages.
3. Сохранить HTML/JUnit/trace и screenshots как GitHub Actions artifacts, добавить
   в документацию реальные commit, PR, run и deployment links.
4. Выполнить `docker compose build` и Connected acceptance на отдельном хосте:
   sandboxed startup, публичная HTTPS-страница, корректный кадр и отказ private URL.

## Remote VM — не начато

[Issue #6](https://github.com/romantic52/BROwOS/issues/6) отслеживает будущий
адаптер внешней виртуальной машины. Для него понадобятся выбранный remote-display
протокол, собственная VM-инфраструктура, управление доступом/сеансом и интеграция
в оболочку. Лицензирование гостевой Windows и ресурсы сервера должны предоставляться
владельцем соответствующей инфраструктуры.

Текущий Node/Chromium-сервис не является этой VM и не запускает `.exe`.
В первом preview нет виртуализации процессора, гостевой ОС или совместимости с
Windows API. Решение о конкретной VM-платформе ещё не принято.

## Правило изменения статуса

`IMPLEMENTED` означает наличие работающей реализации в проверяемом исходном коде.
`TESTED` требует выполненных подходящих проверок с указанием их области.
Задача закрывается после доставки принятого кода в официальный репозиторий.
Наличие локального файла, документа или workflow не доказывает merge, зелёный CI,
запущенный сервер или опубликованный сайт.
