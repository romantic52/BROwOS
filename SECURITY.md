# Безопасность BROwOS

BROwOS 0.1.x — браузерная рабочая среда с отдельным подключаемым Chromium runtime. Документ описывает текущие границы проекта и порядок сообщения о проблемах; он не является заявлением о внешнем аудите или сертификации.

## Сообщить об уязвимости

Если в репозитории доступна кнопка **Security → Report a vulnerability**, используйте [private vulnerability reporting](https://github.com/romantic52/BROwOS/security/advisories/new). Доступность этой функции определяется настройками репозитория и здесь не предполагается автоматически.

Если приватная форма недоступна, создайте Issue только с просьбой предоставить закрытый канал связи. Не публикуйте рабочий exploit, действующий токен, содержимое чужих файлов или сведения о доступном частном сервере. Не используйте выдуманный адрес электронной почты: отдельный security email владелец пока не объявлял.

Для закрытого отчёта подготовьте commit/version, затронутый режим, минимальные шаги воспроизведения, фактическое воздействие и безопасную фикстуру. Проверяйте только собственное окружение или окружение, на проверку которого у вас есть разрешение.

Срок реакции пока не установлен. Исправления принимаются в актуальную `main`; поддержки старых релизных веток в этом раннем проекте не обещано.

## Local Edition

Файлы сохраняются в IndexedDB текущего browser origin. Это не облачная синхронизация, не доступ к дискам компьютера и не шифрованное хранилище. Очистка данных сайта, удаление профиля браузера или завершение приватной сессии может удалить файлы. Для важных данных используйте экспорт и резервные копии.

Системные приложения и SDK работают в одном origin и являются доверенным кодом. VFS проверяет структуру, имена, защищённые системные папки, операции перемещения и версии редактируемых файлов, но не предоставляет многопользовательскую модель прав доступа. Не устанавливайте произвольный недоверенный код как системное приложение.

Терминал исполняет ограниченные команды виртуальной файловой системы. Он не запускает shell хоста, `npm`, PowerShell или `.exe`. Калькулятор использует собственный арифметический парсер без `eval`.

Экран блокировки не имеет парольной аутентификации. Он не должен использоваться как защита файлов от другого человека с доступом к тому же браузерному профилю. Task Manager отображает сведения, которые доступны приложению; случайные значения CPU или системной памяти не являются допустимой заменой измерений.

## Local browser

BROwser разрешает HTTP(S) URL и внутренние страницы BROwOS; исполняемые схемы и credentials внутри URL отклоняются. Внешняя страница отображается в sandboxed iframe без `allow-same-origin`, с ограниченным набором разрешений и `referrerPolicy=no-referrer`.

Встраивание зависит от политики самого сайта. CSP, `X-Frame-Options`, cookies и ограничения браузера могут не позволить открыть страницу внутри Local Edition. BROwOS не снимает эти политики и предлагает внешний браузер или отдельно размещённый Connected runtime.

## Connected Edition

Connected — серверный Chromium с HTTP API. Это один настроенный владелец с bearer credential, а не готовая многопользовательская система учётных записей.

Текущий runtime предусматривает:

- обязательный токен `BROWOS_ACCESS_TOKEN` длиной 32–256 символов и сравнение секретов через digest с constant-time сравнением;
- проверку точных разрешённых frontend origins, ограничения размера запросов, частоты запросов, числа и срока жизни сессий;
- отдельный Chromium context для каждой сессии и проверку владельца при обращении к session ID;
- блокирование частных, loopback, link-local и специальных IP-диапазонов, разрешённые HTTP(S) порты, проверку DNS и отдельный egress proxy;
- блокирование WebSocket, service workers, загрузок, file chooser, разрешений устройства и дополнительных окон в текущей реализации;
- запуск production Chromium с sandbox; ошибка запуска возвращается как ошибка, автоматического перехода на `--no-sandbox` нет;
- передачу Chromium только ограниченного набора переменных окружения, без owner credential.

Docker-конфигурация разделяет frontend, Chromium и egress proxy. Browser service подключён к внутренней сети, а наружу выходит через proxy. Контейнеры имеют ограничения ресурсов, сброшенные capabilities и read-only файловые системы с отдельными временными каталогами. Фактическая работа sandbox и сетевой изоляции должна быть проверена на выбранном хосте перед публикацией.

Изоляция не является доказательством отсутствия уязвимостей Chromium или контейнерного runtime. Поддерживайте браузер, зависимости и хост актуальными. Для внешнего доступа используйте HTTPS и собственный закрытый токен. Не публикуйте незащищённый API в интернете и не монтируйте личные каталоги внутрь browser container.

Токен вводится в интерфейсе подключения и хранится в памяти вкладки. Он отправляется только настроенному API endpoint; пользователь должен проверять этот адрес. Токены не должны попадать в `VITE_*`, URL, логи, screenshots, Git или workflow artifacts. Отозвать credential можно его заменой и перезапуском runtime.

Серверные cookies и состояние страниц принадлежат ephemeral context. Завершение сессии, истечение срока или перезапуск runtime удаляет это состояние. Shared VFS frontend не синхронизируется на сервер автоматически.

## CI, тестовые исключения и публикация

Для управляемых Chromium-тестов существуют явные test-only параметры обхода ограничений тестового исполнителя. Они принимаются только при `NODE_ENV=test` и не являются production-настройкой. Прогон с отключённым тестовым sandbox подтверждает поведение API и браузера, но не развёртывание sandbox на целевом сервере.

CI использует минимальные разрешения чтения, проверяет код, build, зависимости и реальные пользовательские сценарии. Workflow публикации принимает только успешный CI push в `main` официального репозитория, использует проверенный build artifact и не запускает исходники проекта с правами Pages.

Public Pages содержит только статический frontend. Backend, токены и Chromium не размещаются на GitHub Pages. Размещение полнофункциональной серверной версии требует отдельного инфраструктурного окружения.

## Лицензия и сторонние компоненты

Лицензию BROwOS выбирает владелец; этот документ не предоставляет третьим лицам дополнительных прав на код. Уведомления сторонних компонентов сохраняются отдельно, включая материалы Playwright в `docker/THIRD_PARTY_NOTICES.md`.

При обнаружении уязвимости приложите ссылки на затронутые файлы и версию зависимости. Не скрывайте проваленный аудит, не удаляйте защитную проверку ради зелёного CI и не публикуйте неподтверждённый статус безопасности.
